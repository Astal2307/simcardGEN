# SIMRUSH

Игра про выбивание красивых номеров SIM-карт: крути барабан, собирай коллекцию, торгуйся на аукционе и поднимайся в рейтинге.

Исходный однофайловый прототип лежит в [`legacy/prototype.html`](legacy/prototype.html) — дизайн перенесён из него без изменений.

## Стек

| Слой | Технологии |
|---|---|
| Клиент | React 19, TypeScript, Vite, Zustand |
| Сервер | Node.js ≥ 22.13, Fastify 5, встроенный `node:sqlite` (без нативных зависимостей) |
| Realtime | Server-Sent Events |
| Общий код | `@simrush/shared` — типы API, правила игры, форматирование |
| Тесты | Vitest |

## Запуск

```bash
npm install
npm run dev        # сервер :3000 + Vite :5173 (с прокси /api)
```

Открыть http://localhost:5173. В dev-режиме `?r=legendary` в адресе принудительно задаёт редкость спина.

```bash
npm test           # тесты доменной логики
npm run typecheck  # tsc во всех пакетах
npm run build      # сборка клиента и сервера
npm start          # прод: сервер отдаёт API и собранный SPA на :3000
```

Docker:

```bash
docker build -t simrush .
docker run -p 3000:3000 -v simrush-data:/data simrush
```

### Деплой: фронт на GitHub Pages, бэкенд отдельно

GitHub Pages отдаёт только статику, поэтому сервер (API, SQLite, аукцион, SSE) нужно развернуть отдельно — подойдёт любой хостинг с Docker (Render, Fly.io, VPS):

1. **Бэкенд.** Соберите и запустите `Dockerfile`, примонтируйте том в `/data` (там база). Задайте `CORS_ORIGIN=https://<user>.github.io` и `NODE_ENV=production`.
2. **Адрес бэкенда для фронта.** В репозитории: Settings → Secrets and variables → Actions → Variables → `API_URL` = адрес бэкенда (напр. `https://simrush-api.onrender.com`).
3. **Pages.** Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` на каждый пуш в `main` проверяет типы, гоняет тесты, собирает фронт (с `VITE_BASE=/<repo>/` и `VITE_API_URL`) и публикует его.

После изменения `API_URL` перезапустите workflow (Actions → Deploy frontend to GitHub Pages → Run workflow).

## Архитектура

**Сервер — источник правды.** В прототипе всё жило в браузере; теперь RNG, баланс, коллекция и аукцион считаются на сервере, клиент только отображает и анимирует. Подменить результат спина или баланс из DevTools нельзя.

**Слои сервера:** `http → services → repositories → db`. Сервисы не знают про HTTP, репозитории — про бизнес-правила. Часы, RNG и канал уведомлений внедряются через `ServiceContext`, поэтому логику легко тестировать детерминированно.

**Транзакции и уведомления.** Каждая операция выполняется в `unitOfWork`: SQL-транзакция плюс `Outbox`, в который копятся события. Они уходят клиентам только после коммита, поэтому откат не порождает «фантомных» тостов.

**Деньги на аукционе — через эскроу.** Ставка сразу списывается с баланса и возвращается, если лидера перебили. Баланс меняется атомарно (`UPDATE … WHERE balance + Δ >= 0`) и не может уйти в минус.

**Рынок.** Тикер раз в секунду закрывает истёкшие лоты, разыгрывает ставки ботов и держит на рынке 6 бот-лотов. Лоты игроков видны всем, на них ставят и другие игроки, и боты. Ставка в последние 6 секунд продлевает лот (кроме ставок ботов на лоты игроков).

**Realtime.** `GET /api/events` — SSE-поток: `lots` (снимок рынка при каждом изменении), `balance`, `collection`, `quests`, `notice`. При переподключении клиент сверяет коллекцию.

**Ежедневный бонус.** Награда растёт с 1-го по 7-й день серии (`DAILY_BONUS_REWARDS` в `shared/rules.ts`). После 7-го дня каждый день даёт награду 7-го, пропуск дня сбрасывает серию. Игровой день меняется в полночь по `GAME_TZ_OFFSET_MIN`. Повторное получение за один день блокируется условием в `UPDATE`, поэтому даже параллельные запросы не начислят бонус дважды.

**Ежедневные задания.** На каждый игровой день игрок получает 3 задания разных видов из пула (`domain/quests.ts`); первое всегда на спины. Задания создаются лениво при первом обращении или действии. Сервисы засчитывают прогресс внутри своей транзакции через `QuestService.track()`: спин, редкий спин, ставка, выигранный аукцион, выставленный и проданный лот, мгновенная продажа. Готовое задание присылает `notice: quest_done` и обновлённый список `quests` по SSE. Награду нужно забрать вручную, задания прошлых дней сгорают.

**Гарантии и апгрейды.** Тир = редкость (1 — обычный … 5 — легендарный). Гарантия «каждая N-я ≥ тир T»: для каждого тира на сервере ведётся счётчик круток (`pity`); когда он доходит до N, крутка разыгрывается только среди тиров ≥ T (пропорции шансов сохраняются), счётчик обнуляется. База — каждая 10-я ≥ тир 2. Дерево (`shared/upgrades.ts`): ветка периода 10 → 9 → 8 → 7 и ветка порогов ≥ тир 3 / 50, ≥ тир 4 / 200, ≥ тир 5 / 1000; узел покупается после предыдущего в ветке. Счётчики возвращаются в ответе спина и показываются на клиенте только после раскрытия номера.

**Коллекции.** 13 коллекций в трёх группах (`shared/album.ts`): простые — пары, круглые хвосты, коды операторов; средние — тройки, лесенки, зеркала, повторы XY, даты; редкие — монолит, код в тон, две цифры, математика, отсылки (хвост заканчивается на 1337 / 228 / 314159 / 0451 или начинается с 4815). Каждая коллекция — набор ячеек с признаком по цифрам; ячейку закрывает первый подходящий номер (спин или выигранный аукцион), один номер может закрыть несколько ячеек. Генератор номеров подстроен, чтобы узоры коллекций реально выпадали: коды чаще из пула операторов, обычные иногда с датой, необычные — с круглым хвостом, редкие — с зеркалом, эпические — с «математикой» или «отсылкой». Новые ячейки приходят в ответе спина; после раскрытия номера клиент показывает карточку сверху, точки летят с SIM-карты в прогресс-бары коллекций. За полностью собранную коллекцию игрок один раз забирает награду (`reward` в определении коллекции; простые 2–3 тыс., средние 8–15 тыс., редкие 40–150 тыс.), на вкладке горит точка, пока награда не забрана.

**Мастерская** (вкладка «Номера» → «Крафт» / «Апгрейд»). Редкость номера определяется по узору хвоста (`classifyRarity`, те же узоры, что у генератора).
- *Крафт*: сжечь три номера одной редкости R, выбрать позицию (кроме первой 9) в четвёртом номере редкости не выше R+1 — цифра на ней заменится случайной. Потолок тира: цифры, при которых номер стал бы выше R+1, в розыгрыш не входят. После замены редкость пересчитывается; если она изменилась, стоимость разыгрывается заново.
- *Апгрейд*: жертва + желаемый номер (любые цифры). Колесо из 40 секторов; число выигрышных зависит от разницы редкостей желаемого и жертвы: 38 / 34 / 24 / 12 / 5 / 2 / 1 для −2 / −1 / 0 / +1 / +2 / +3 / +4. Сектор выбирает сервер, жертва сгорает в любом случае, при выигрыше игрок получает желаемый номер. Первый апгрейд нового игрока всегда выигрывает: колесо и шанс показываются обычные, но сервер ставит стрелку на выигрышный сектор (`users.free_upgrade`; у существующих игроков миграция ставит 0).
Оба действия засчитывают новый номер в коллекции.

**Обучение.** Новый игрок за 25 шагов сам проходит всю игру: 3 крутки (подсвечены барабан, результат и кнопка) → шансы и гарантия → забирает ежедневный бонус, видит задания → крафт (выбирает номер, позицию, три номера на сжигание) → апгрейд номера на колесе → коллекции → ставка на аукционе (подсвечивается самый дешёвый доступный лот) → покупка гарантии в дереве → рейтинг. Экран затемняется, подсвечивается нужный элемент; на шагах-действиях клики проходят только в подсветку, при открытом выборе номера подсветка переходит на него. Чтобы крафт гарантированно сложился, стартовый набор — 3 обычных + необычный + редкий, а в обучении выбор ограничен обычными/необычными. Если действие невозможно (нет денег, нет лотов), появляется «Далее». Прогресс хранится на сервере (`users.tutorial_step`, −1 — пройдено); для уже существующих игроков миграция отмечает обучение пройденным; `?tutorial` в адресе запускает его заново.

**Авторизация** — гостевая: `POST /api/session` выдаёт токен, клиент хранит его в `localStorage`.

## API

| Метод | Путь | |
|---|---|---|
| POST | `/api/session` | создать гостевой аккаунт |
| GET | `/api/me` | профиль и баланс |
| POST | `/api/tutorial` | сохранить шаг обучения `{ step }` (−1 — пройдено) |
| POST | `/api/wallet/topup` | демо-пополнение +5 000 |
| POST | `/api/spin` | спин (`{ rarity? }` только в dev) |
| GET | `/api/bonus` | статус ежедневного бонуса |
| POST | `/api/bonus/claim` | забрать бонус за сегодня |
| GET | `/api/album` | закрытые ячейки коллекций и полученные награды |
| POST | `/api/album/:id/claim` | забрать награду за собранную коллекцию |
| GET | `/api/upgrades` | купленные апгрейды и счётчики гарантий |
| POST | `/api/upgrades/:id/buy` | купить апгрейд |
| GET | `/api/quests` | задания дня |
| POST | `/api/quests/:id/claim` | забрать награду за задание |
| GET | `/api/sims` | коллекция |
| POST | `/api/sims/:id/sell` | мгновенная продажа за 70 % |
| POST | `/api/sims/sell-many` | мгновенная продажа нескольких `{ ids }` (номера не из инвентаря пропускаются) |
| POST | `/api/sims/:id/list` | выставить на аукцион `{ startPrice }` |
| POST | `/api/craft` | крафт `{ targetId, burnIds, position }` — цифру выбирает сервер |
| POST | `/api/upgrade` | апгрейд `{ sacrificeId, digits }` |
| GET | `/api/lots` | открытые лоты |
| POST | `/api/lots/:id/bid` | ставка |
| POST | `/api/lots/:id/cancel` | снять свой лот без ставок |
| GET | `/api/leaderboard?by=value\|count` | рейтинг |
| GET | `/api/events?token=` | SSE-поток |

Ошибки возвращаются как `{ error: ErrorCode, message }` с HTTP-статусом 4xx/5xx.
